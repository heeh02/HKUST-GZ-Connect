# 面向学校部署的易用性与网络隔离方案

## 目标用户

产品需要同时覆盖三类人，而不是让所有人学习 Clash：

| 用户 | 默认操作 | 需要暴露的概念 |
| --- | --- | --- |
| 只访问校内网站的师生 | 登录 → 点击常用服务 | 不暴露端口、PAC、DNS |
| 需要 SSH/数据库/开发工具的用户 | 登录 → 复制应用配置 | SOCKS/PAC/SSH |
| 需要所有校园应用透明工作的用户 | 安装学校签名的系统组件 → 启用智能模式 | 只显示模式与连接状态 |

当前版本已经完成第一类路径，并保留第二类路径。第三类不能靠修改几个系统 DNS
命令可靠实现，应作为独立、签名、可回滚的平台前端建设。

## 当前默认：隔离校园浏览器

应用内校园浏览器使用独立 Electron 会话，把该会话的 HTTP/HTTPS 请求全部交给
本机代理，再由 Rust 用户态网络栈进入校园隧道。

它具有以下特性：

- 不依赖 Chrome、Clash 或浏览器扩展；
- 不读取日常浏览器的 Cookie、历史或插件；
- 不修改系统 DNS、默认路由和全局代理；
- 隧道断开时连接失败关闭，不会静默直连泄露请求；
- 保留普通浏览器式多标签页、地址栏、前进、后退、刷新及键盘快捷键；
- 页面失败时显示本地错误页，避免把隧道、权限或网址错误表现成空白窗口；
- 对 HTTPS 登录表单提供显式确认的本机密码保存；按来源隔离并使用系统凭据服务
  加密，不向诊断、遥测或维护端导出；
- 通过隧道内双站点健康探测识别“进程存活但数据面假死”，连续失败后自动重连；
- 支持学校主页、一站式办事大厅、图书馆、迎新系统及任意粘贴网址；
- 常用入口保存在独立、可审查的资源清单中。

学校后续可用签名资源清单替代随版本发布的静态清单。签名内容只能包含显示名、
类别和 HTTPS URL，更新失败时继续使用最后一个验证通过的版本。

## EasyConnect 与 zju-connect 中值得吸收的设计

可以借鉴的行为设计：

- 用户态网络栈与上层代理前端解耦；
- SOCKS、HTTP、透明访问作为可替换前端，而非写入协议核心；
- 自动重连、保活、连接取消和明确的被动下线原因；
- “规则访问”和“全部通过”是两个清楚的用户模式；
- 资源列表驱动入口，不要求用户手工维护所有域名。

不应重新引入的做法：

- 把账号密码写入运行配置文件；
- PAC 中调用 `dnsResolve()` 再判断内网地址；
- 为连接网关依次查询硬编码公共 DNS；
- 用 shell 或命令解释器拼接浏览器参数；
- 默认替换系统 DNS、全局代理或默认路由；
- 在未知认证方式出现时把它显示成“密码错误”。

借鉴限于架构和用户体验，不重新建立对外部项目二进制、仓库或发布节奏的运行时
依赖。

## 可选智能系统模式

要让 Outlook、数据库客户端、IDE 和普通浏览器无需单独配置，建议建设平台原生
前端，而不是让桌面主进程执行临时网络命令：

### macOS

- 使用签名并公证的 Network Extension；
- 只声明网关下发的校园网段路由；
- 内部域名使用 scoped/match-domain DNS；
- 配置由系统框架拥有，扩展停止时系统负责撤销；
- 通过学校 MDM 安装、授权和回滚。

### Windows

- 使用签名的 WFP/平台网络组件；
- 只截获资源策略匹配的目标；
- 内部域名使用受管的分域解析策略；
- 安装器记录组件版本并支持原子升级/卸载；
- 不使用永久写入网卡 DNS 的脚本。

系统模式必须满足：

1. 默认关闭，普通网站访问不需要它；
2. 连接前记录平台配置版本，断开后验证撤销；
3. 崩溃和断电后由系统组件租约过期或下次启动自动修复；
4. 校园资源以外默认直连；
5. 管理员可完全禁止“全部通过”；
6. 不支持的平台继续使用隔离浏览器和显式代理。

在获得 Developer ID、Windows 代码签名证书、MDM 策略和专门测试设备前，不应
把这种模式伪装成“已完成”。

## 学校运营能力

要从个人工具变成学校服务，还需要：

- **签名与自动更新**：学校证书签名，分员工试用、灰度、全量三阶段；保留上一
  版本一键回滚。
- **受管网关配置**：网关地址、证书 pin、协议适配器和资源清单由签名配置管理，
  用户界面不允许任意改写生产网关。
- **MFA 完整状态机**：验证码、短信、动态令牌、证书、浏览器 SSO、密码到期和
  设备审批都通过版本化控制协议接入。
- **一键诊断**：只导出版本、阶段、错误码、计数和哈希；账号、Cookie、Token、
  内部 URL、分配地址和原始包默认不进入诊断包。
- **双语与无障碍**：桌面字符串迁移到中英文资源文件，支持键盘操作、读屏和
  高对比度。
- **服务台流程**：界面直接区分账号错误、MFA 未支持、网关升级、端口占用、
  数据面掉线和目标无权限。
- **应急兜底**：保留厂商支持客户端与独立管理通道，HKUST(GZ) Connect 不应
  成为管理员唯一恢复路径。

## 建议实施顺序

1. 隔离校园浏览器、常用资源、一键连接和面向普通用户的 README；
2. 结构化引擎事件、MFA 交互协议、资源列表提供器；
3. 签名更新、诊断包、学校托管的资源/配置清单；
4. macOS/Windows 平台原生智能模式；
5. 在测试网关逐项启用 CAPTCHA、短信、令牌、证书和 SSO 做黑盒验收。

任何阶段都不能用“未来兼容”代替真实验收。未启用功能可以预留稳定接口，但只有
在学校控制的测试配置上通过官方客户端与独立客户端对照后，才能标记为支持。
