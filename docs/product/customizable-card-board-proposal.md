# HKUST(GZ) Connect 可定制卡片工作台重构 Proposal

> 状态：**已获用户批准并进入实施**
> 日期：2026-08-31  
> 适用版本：2.0.1 Beta 后续迭代  
> 本文只定义产品、交互、数据与实施合同；批准前不实施产品代码，不创建执行 Goal。

## 1. 执行摘要

当前问题不是再调一次阴影或间距就能解决，而是“浏览”和“整理”仍是两套产品：

- 控制窗口中的卡片只是运行时投影；
- 点击“整理”会跳进校园浏览器内另一套列表式管理页；
- 当前堆叠把大量分类标题纵向压在一起，既不像扑克牌，也不像高效的桌面工具；
- 网站列表是否双列取决于外层堆叠列数，而不是卡片自身宽度，所以窗口越宽反而可能仍是单列；
- 分类顺序、卡片堆叠、卡片尺寸和页面摆放都没有统一、可持久化的数据模型；
- 连接页有较大空白，却不能承载用户真正高频的校园网站卡片。

建议将产品升级为一个**受约束的可定制卡片工作台**：

1. “整理”不再打开另一套页面，而是在当前页面进入原位编辑模式；
2. 卡片默认紧凑陈列，悬停轻微抬起；点击后在原位置展开，同组其他卡片收成标题条；
3. 卡片内部根据自身宽度自动显示一列或两列网站，不再由外层列数错误决定；
4. 编辑模式允许像整理扑克牌一样插入、换位、叠成一组、从组中抽出；
5. 用户可以把校园分类卡片固定到连接页，但这只是增加一个布局引用，不会从校园浏览器或官方目录中删除原卡片；
6. 连接状态和连接开关保持固定安全锚点，不能被拖走、覆盖或删除；
7. 物理像素位置不持久化，只保存逻辑顺序、卡组和尺寸，保证 macOS、Windows、Linux 与不同窗口尺寸下都能恢复。

视觉目标不是模仿 iOS/macOS Widget 的材质，而是借鉴其核心原则：

> **卡片可识别、可移动、可调整尺寸；系统布局有秩序；用户可以个性化，但无法把核心功能拖坏。**

### 明确非目标

- 不修改 EasyConnect Engine、认证、路由或代理逻辑；
- 不把控制塔改成自由拖放工作台；高风险设置仍使用稳定模块网格；
- 不保存任意像素坐标，不允许卡片互相遮挡；
- 不允许隐藏、移动或删除连接开关和错误恢复；
- 不复制一套官方分类数据，Card Board 只引用现有 taxonomy；
- 不引入远程 Widget、插件市场、新闻、公告或文件模块；
- 不在普通浏览模式开启拖动。

## 2. 当前实现复盘

### 2.1 “整理”入口与当前页面脱节

当前控制窗口的“整理”按钮在 `desktop/renderer/app.js:548-552` 调用
`openBookmarkManager()`；Main 再由
`desktop/lib/browser/session/campus-browser-manager.js:218-227` 打开 Campus Workspace，
并强制切到 `manage` 页面。

因此截图一中的卡片堆叠与整理页没有共享同一布局：用户看到什么、整理什么并不是同一对象。

### 2.2 现有堆叠是“长标题瀑布”，不是可操作卡组

`desktop/renderer/campus-category-stacks.js:124-131` 将同一 stack 的非活动分类全部渲染成
纵向标题条，再把活动卡片放在最下方。分类多时会形成截图二的长瀑布：

- 需要穿过十余个标题才能看到内容；
- 点击后整组重新生成 HTML，视觉连续性弱；
- 卡片无法离开当前自动分区；
- 用户不能决定哪几张牌属于同一叠；
- 窗口变化会重新分区，用户没有稳定的空间记忆。

### 2.3 网站双列规则方向相反

`desktop/renderer/styles.css:1302-1304` 只在外层 `data-stack-columns="1"` 时，
把网站列表变成两列。外层一旦扩展成三列，每张卡反而退回单列。

正确依据应该是**单张展开卡片的可用宽度**，不是整个工作台有几列。

### 2.4 现有收藏分组不等于页面布局

`favorite-groups.json` 负责用户收藏的多对多归组和组顺序；它不应继续承担：

- 卡片位于连接页还是校园浏览器；
- 卡片是否与其他卡片叠成一组；
- 卡片展示尺寸；
- 卡片在工作台中的插入位置。

如果把这些布局状态塞回收藏分组，会再次把“数据归类”和“界面摆放”混成一个概念。

### 2.5 连接页可以承载卡片，但需要安全边界

连接页目前分为连接主卡、IP/延迟、网卡树和更多连接信息。它适合增加用户卡片区域，
但连接开关、连接状态、错误恢复不能参与自由拖拽，否则会损害核心产品任务。

## 3. 产品概念模型

### 3.1 五个必须分开的概念

| 概念 | 含义 | 是否可由用户修改 |
| --- | --- | --- |
| 网站资源 Resource | 一个可打开的网站与其路由信息 | 自定义资源可编辑；官方资源只读 |
| 官方分类 Official Category | 学校维护的任务分类 | 内容不可改；显示位置可改 |
| 用户分类 User Collection | 用户按自己用途建立的网站集合 | 可改名、增删网站、排序 |
| 卡片 Card | 对分类或系统功能的可视化引用 | 可调整显示尺寸和摆放 |
| 放置 Placement | 某张卡片在某个工作台中的位置 | 可移动、堆叠、复制到其他工作台 |

关键规则：

- 拖动卡片只改变 `Placement`，不会改变网站官方分类；
- 将卡片放到连接页是“固定一个引用”，不是把分类从校园浏览器移走；
- 同一分类可同时出现在校园浏览器和连接页；
- 删除连接页上的卡片只删除该 Placement，不删除分类、收藏或网站；
- 网站路由、EasyConnect 连接和收藏状态不由布局系统修改。

### 3.2 卡片类型

第一阶段只支持以下明确类型：

```text
official-category     官方任务分类
user-collection      用户分类
ungrouped-favorites  未分类收藏
connection-metrics   校园 IP + 延迟
network-adapter      当前连接网卡
connection-details   更多连接信息
```

不新增校园公告、校园文件、新闻或其他业务模块。

## 4. 目标交互

## 4.1 普通浏览模式：点击原位展开

不再把 12 个分类全部压成一根长瀑布。

建议结构：

```text
┌─────────────────────┐  ┌─────────────────────┐
│ 课程、选课与成绩  10 │  │ 科研、进度与计算   7 │
└─────────────────────┘  └─────────────────────┘

点击“科研、进度与计算”后：

┌──────────────────────────────────────────────┐
│ 科研、进度与计算                          7  │
├──────────────────────────────────────────────┤
│ [图标] 论文答辩系统   [图标] RPMS             │
│        直连                  校园隧道         │
│ [图标] APR            [图标] QPE              │
│        直连                  直连             │
│ [图标] 校园 AIGC      [图标] HPC 指南         │
│        直连                  直连             │
└──────────────────────────────────────────────┘

┌─────────────────────┐  ┌─────────────────────┐
│ 实验室与仪器       2 │  │ 学费、奖助与津贴   2 │
└─────────────────────┘  └─────────────────────┘
```

行为合同：

- 卡片默认只显示 40–44px 标题行、数量和轻量类别图标；
- 鼠标悬停上移 2px，并增强边框，不展开内容；
- 点击卡片后，该卡片在当前位置展开；
- 同一卡组中的其他卡片收成标题行；
- 宽屏下其他列保持原位，不做全页面跳动；
- 再次点击展开卡片可收起；
- 点击另一张卡片时，旧卡片收起，新卡片原位展开；
- 打开网站不会改变卡片布局；
- 每个卡组保留自己的当前活动卡片。

不采用夸张的 3D 翻牌、倾斜和弹跳。扑克牌隐喻用于“插入、成组、抽出和置顶”，
而不是用于装饰。

## 4.2 卡片内部网站密度

网站布局由卡片自身的 container query 决定：

| 展开卡片内容宽度 | 网站列数 |
| --- | --- |
| `< 440px` | 1 列 |
| `440–719px` | 2 列 |
| `≥ 720px` | 2 列，增加列间距，不继续扩成 3 列 |

网站行规格：

- 行高 50–56px；
- 图标容器 28×28px，图标本体 16px；
- 名称 13–14px，最多两行；
- 路由 11.5–12px；
- 星标 18px；
- 不再强制单行省略长名称；
- 不再使用内层永久滚动条。

卡片最多先展示 12 个网站；超过 12 个时显示“展开全部（N）”，点击后卡片自然增高，
页面滚动，不形成页面滚动 + 卡片滚动的双层滚动。

## 4.3 “整理”改为当前页面原位编辑

点击“整理”后，不打开 Campus Workspace 管理页，而是当前工作台进入编辑模式：

```text
校园浏览器                         [撤销] [重做] [恢复布局] [完成]

┌──────────────┐   ┌──────────────┐   ┌──────────────┐
│ ⠿ 课程…   ⋯  │   │ ⠿ 科研…   ⋯  │   │ ⠿ 实验…   ⋯  │
│ 插入位置预览  │   │              │   │              │
└──────────────┘   └──────────────┘   └──────────────┘
```

编辑模式提供：

- 拖动卡片改变顺序；
- 将卡片拖到两张卡之间插入；
- 将卡片拖到另一张卡中央，形成一叠；
- 将卡片从一叠中拖出，变成独立卡片；
- 拖动尺寸手柄切换小、中、大三档；
- 用户分类可重命名、删除；
- 官方分类不可重命名、删除，但可从当前自定义工作台隐藏并随时恢复；
- 卡片菜单提供“固定到连接页”“从当前页面移除”“恢复默认位置”；
- 普通浏览模式不启用拖动，防止误操作。

编辑过程先保存在内存草稿中：

- “撤销 / 重做”只修改草稿；
- 点击“完成”一次性原子提交；
- 离开页面时若有未保存修改，显示“保存 / 放弃 / 继续整理”；
- 保存失败恢复旧布局，并显示明确错误，不部分提交。

## 4.4 拖放判定：插入与成叠必须明确

每张卡片使用三个 Drop Zone：

```text
┌─────────────────────────────────┐
│ 上边缘 24%：插入到这张卡之前     │
│                                 │
│ 中央 52%：与这张卡叠成一组        │
│                                 │
│ 下边缘 24%：插入到这张卡之后       │
└─────────────────────────────────┘
```

视觉反馈：

- 插入：显示 2px 深蓝插入线和占位轮廓；
- 成叠：目标卡片整体出现淡金描边，标题显示“叠放到这里”；
- 非法目标：不显示 Drop Zone，鼠标提示禁止；
- 拖动越过侧栏“连接”并停留 500ms，可弹簧式切换到连接页；
- 键盘和菜单提供等价操作，不要求用户一定能拖动。

## 4.5 连接页中的用户卡片

连接页分成两个边界：

### 固定安全区

不能移动、删除或覆盖：

- 当前学校；
- 连接状态；
- 连接/断开开关；
- 错误与重试；
- 认证挑战。

### 可定制卡片区

允许重排：

- 校园 IP 与延迟；
- 当前连接网卡；
- 更多连接信息；
- 用户固定过来的官方分类或个人分类卡片。

推荐宽屏结构：

```text
┌───────────────────────┬──────────────────────────────┐
│ 固定连接控制           │ 可移动：连接网卡              │
├───────────┬───────────┼──────────────────────────────┤
│ 可移动 IP │ 可移动延迟 │ 固定到连接页的“科研”卡片       │
└───────────┴───────────┴──────────────────────────────┘
```

跨页面拖放的默认语义是**固定副本**：

- 拖到连接页后，校园浏览器中的原卡片仍存在；
- 两个 Placement 引用同一个分类；
- 从连接页移除不影响分类和网站；
- 若分类被真正删除，所有对应 Placement 由 Main 统一清理。

这是推荐方案，比“从一个页面搬走”更安全，也更符合 macOS Widget 的固定语义。

## 5. 响应式与窗口模型

## 5.1 不保存绝对像素坐标

“自由摆放”不能等价于保存任意 `x/y/width/height`：那会在窗口缩放、200% 缩放、
Windows 字体和中英文切换后发生重叠。

系统保存：

- board；
- logical order；
- deck；
- size preset；
- span；
- visible/hidden。

系统运行时计算物理位置。

## 5.2 推荐网格

| 主内容宽度 | 卡片槽位 |
| --- | --- |
| `< 760px` | 单列，按 logical order 排列 |
| `760–1099px` | 2 列 |
| `1100–1439px` | 3 列 |
| `≥ 1440px` | 最多 4 列，内容宽度封顶 |

卡片尺寸：

- S：1 个槽位；
- M：2 个槽位；
- L：整行；
- 窄窗口中所有尺寸自动降级为单列，但 logical order 不变。

## 5.3 默认窗口

建议新安装默认窗口为 **1024×576（16:9）**，最小窗口为 **820×540**。

- 已明确保存过窗口尺寸的现有用户继续恢复自己的尺寸；
- 设置中增加“恢复默认窗口和布局”；
- 不在升级时强制覆盖用户已保存的窗口位置。

## 6. 视觉系统

## 6.1 卡片层级

| 状态 | 视觉 |
| --- | --- |
| 紧凑 | 1px 中性边框、无阴影、40–44px 高 |
| Hover | 上移 2px、边框变深、120ms |
| 展开 | 白色内容面、轻阴影、圆角 14–16px |
| 编辑 | 左上拖动柄、右上菜单、淡虚线槽位 |
| 拖动 | 0.98 scale、活动阴影、70% 原位占位 |
| Drop target | 插入线或淡金成叠描边 |

颜色职责继续沿用 HKUST 深蓝和金色：

- 深蓝：结构、选中、插入线；
- 金色：收藏、成叠目标、少量品牌点缀；
- 绿色：连接成功；
- 不给每张卡增加大面积渐变或厚金边；
- 分类色只用于 2px 边缘、图标底色或小圆点。

## 6.2 动效

统一缓动：`cubic-bezier(0.2, 0.8, 0.2, 1)`。

| 动作 | 时长 |
| --- | ---: |
| Hover | 120ms |
| 卡片展开/收起 | 200–220ms |
| 卡片置顶 | 220ms |
| 拖放重排 FLIP | 240–260ms |
| 跨页面弹簧切换 | 180ms |

实现原则：

- 拖动过程中只更新 `transform` 和 `opacity`；
- 拖动开始时一次性缓存可落点矩形；
- 每帧最多一次 `requestAnimationFrame`；
- 不在 `pointermove` 中重建全部 HTML；
- 停止窗口缩放 120ms 后再执行一次 FLIP；
- `prefers-reduced-motion` 下立即完成位置变化，只保留极短淡入。

## 7. 数据模型

新增独立布局文档，不修改现有收藏、分类和路由文档：

```ts
type CardRef =
  | { kind: "official-category"; id: CategoryId }
  | { kind: "user-collection"; id: CollectionId }
  | { kind: "system-widget"; id: SystemWidgetId };

type CardPlacement = {
  placementId: string;
  boardId: "browser-catalog" | "browser-personal" | "connect";
  card: CardRef;
  deckId: string | null;
  order: number;
  size: "small" | "medium" | "large";
  hidden: boolean;
};

type CardDeck = {
  deckId: string;
  boardId: CardPlacement["boardId"];
  placementIds: string[];
  activePlacementId: string;
  order: number;
};

type CardBoardLayoutDocument = {
  schemaVersion: 1;
  revision: number;
  placements: CardPlacement[];
  decks: CardDeck[];
};
```

约束：

- 最多 96 个 Placement；
- 最多 32 个 Deck；
- 单 Deck 最多 16 张卡；
- 同一 board 中同一 CardRef 默认最多一个 Placement；
- `connect` 可以引用 `browser-*` 已存在的卡；
- 不保存 HTML、URL、颜色、任意 CSS 或文件路径；
- CardRef 必须在 Main 当前权威资源/分类中解析成功；
- 固定连接控制不进入此文档。

建议文件：

```text
<profile workspace>/card-board-layout.json
```

采用现有原子写入、owner-only 权限、Windows DACL、符号链接/硬链接拒绝和目录 fsync 合同。

## 8. 工程结构

不继续把逻辑堆进 `app.js`、`campus-workspace.js` 或 `styles.css` 文件末尾。

建议结构：

```text
desktop/lib/card-board/
  schema/
    card-board-contract.js
  runtime/
    card-board-store.js
    card-board-runtime.js
    card-board-migration.js

desktop/lib/ipc/
  card-board-ipc.js

desktop/renderer/components/card-board/
  card-board-model.js
  card-board-controller.js
  card-board-view.js
  card-board-drag.js
  card-board.css

desktop/renderer/
  app.js                         # 只做 composition
  campus-workspace.js            # 只做 Workspace composition
```

CSS 策略：

- 把现有 `.category-stack-*` 与 `.category-site-*` 规则从 `styles.css` 移出；
- `card-board.css` 使用命名空间或 CSS cascade layer；
- 不追加“下一代 polish”覆盖块；
- Control 页面与 Campus Workspace 共同加载同一 Card Board 组件；
- 控制塔的网站规则卡可复用网站行视觉，但不复用可自由摆放的数据语义。

Main/Preload 边界：

```text
Renderer draft operations
        │ only IDs + bounded operations
        ▼
Preload schema validation
        ▼
CardBoard IPC
        ▼
CardBoardRuntime transaction
        ▼
owner-only atomic layout store
```

Renderer 不发送 URL 来标识卡片，也不能写文件。

## 9. 整理事务与命令

建议一次编辑会话使用一个 revision-bound draft：

```ts
begin-layout-edit(revision)
preview-layout-operations(operations) // Renderer local only
commit-layout-edit({ baseRevision, operations })
cancel-layout-edit()
```

允许的原子操作：

```text
move-placement
insert-placement
```

## 10. 升级与恢复

## 10.1 首次生成默认布局

升级时不迁移 URL，也不重写收藏：

1. `browser-catalog` 按官方 taxonomy 顺序生成卡片；
2. `browser-personal` 按现有 collection 顺序生成卡片；
3. 未分类收藏生成一张 `ungrouped-favorites` 卡；
4. `connect` 保持系统默认卡片，不自动添加校园分类；
5. 用户以后主动固定到连接页。

## 10.2 官方目录变化

- 新增官方分类：追加到未自定义位置之后；
- 分类删除：对应 Placement 安全退休，记录迁移 receipt；
- 分类重命名：CardRef ID 不变，显示名称自动更新；
- 用户布局顺序不因资源增减整体重排。

## 10.3 恢复默认

恢复布局只重建 `card-board-layout.json`：

- 不删除收藏；
- 不删除用户分类；
- 不删除自定义网站；
- 不修改路由规则；
- 不修改连接配置。

## 11. 可访问性

拖放必须有完整的非鼠标等价操作：

- `Space` 拿起/放下卡片；
- 方向键移动插入位置；
- `Enter` 展开卡片；
- `Escape` 取消拖动或退出编辑；
- 菜单提供“前移、后移、叠放、移出卡组、固定到连接页”；
- 屏幕阅读器播报“已移动到第 2 列第 3 位”；
- 焦点在重新排布后仍跟随同一 CardRef；
- 200% 缩放无横向溢出；
- Reduced Motion 不依赖动画传达状态。

## 12. 性能与延迟预算

| 场景 | 目标 |
| --- | ---: |
| 45 个资源 + 12 个官方分类首次投影 | JS 主线程 `< 50ms` |
| 卡片点击展开到首帧 | `< 100ms` |
| 拖动帧率 | p95 frame `< 16.7ms` |
| 120 个网站搜索 | `< 30ms` |
| 布局保存 | 本地 p95 `< 100ms` |
| 窗口缩放后稳定重排 | 停止缩放后 `< 280ms` |

措施：

- Card Board 使用 keyed DOM，更新受影响卡片，不重建整个页面；
- 拖动时不读取网络状态、不触发路由解析、不写磁盘；
- 搜索与连接遥测不共享高频渲染循环；
- Layout Store 与 FavoriteGroupStore 分离，互不加锁；
- 不引入远程图标或网络依赖。

## 14. 实施阶段与并行方案

批准后将创建一个 Goal，建议目标为：

> 在不修改 EasyConnect 核心连接引擎和既有路由语义的前提下，实现可持久化、跨页面、
> 响应式且可访问的卡片工作台；统一控制窗口与 Campus Workspace 的浏览/整理体验。

### Phase 0：RED 合同与视觉基线

- 固定当前错误行为测试；
- 建立 16:9、宽屏、窄屏截图基线；
- 锁定数据 schema 和安全边界。

### Phase 1：Card Board 数据域

- schema、store、runtime、migration；
- 原子提交、revision、恢复默认；
- 不接 UI。

### Phase 2：共享 Card Board 组件

- 紧凑/展开卡片；
- container query 双列网站；
- hover、focus、Reduced Motion；
- 替换当前瀑布堆叠。

### Phase 3：原位整理

- 编辑模式；
- 插入、叠放、抽出；
- undo/redo；
- 键盘等价操作；
- “整理”不再跳转另一套页面。

### Phase 4：连接页工作台

- 固定安全区；
- 可移动系统卡片；
- 跨页面固定分类卡；
- 弹簧式侧栏 Drop Target。

### Phase 5：Campus Workspace 收束

- 复用同一 Card Board；
- 删除重复管理 UI；
- 保留完整网站管理的上下文菜单/Sheet。

### Phase 6：回归、打包与发布

- 全量测试；
- 三平台 package verifier；
- macOS 本地构建覆盖；
- 清理旧应用与构建垃圾；
- PR 和 CI。

### 多 Agent 并行车道

在 Phase 0 schema 锁定后可并行：

| 车道 | 负责范围 | 禁止交叉修改 |
| --- | --- | --- |
| A：数据与 Main | schema/store/runtime/IPC/migration | 不改 Renderer 样式 |
| B：Card Board UI | model/view/drag/CSS/键盘 | 不改持久化格式 |
| C：测试与性能 | E2E、视觉回归、性能、跨平台 | 不直接重写产品实现 |
| Root：集成 | composition、冲突解决、最终体验、构建与 PR | 只在合同变更时协调三车道 |

每个车道先 RED 测试，再实现；共享文件由 Root 独占，避免并行互相覆盖。

## 15. 验收标准

以下条件全部满足才可完成 Goal：

### 整理一致性

- 点击“整理”在当前页面进入编辑模式；
- 不再打开与当前卡片布局无关的管理页；
- Campus Workspace 与控制页使用同一布局模型；
- 用户看到的顺序就是保存后的顺序。

### 卡片体验

- Hover 有克制抬起反馈；
- 点击在原位置展开；
- 同组其他卡片缩为标题；
- 展开不会把其他列全部推离视口；
- 大于等于 440px 的卡片内部网站一排两个；
- 不出现永久内层滚动条；
- 长名称可读。

### 自由摆放

- 编辑模式可插入、换位、叠放和抽出；
- 拖到卡片边缘与中央产生不同结果；
- 可将分类固定到连接页；
- 从连接页移除不会删除分类、收藏或网站；
- 布局重启后保持；
- 窄屏重排不破坏逻辑顺序。

### 连接安全

- 连接开关和状态不可被拖走、隐藏或覆盖；
- EasyConnect Engine、凭据、路由和网络规则不因布局修改；
- 布局失败不影响连接；
- 固定卡片不能读取连接凭据。

### 质量

- 架构门不增长 Main/app God Module；
- 无新增未说明 CSS 覆盖层；
- 1133 项现有测试保持通过；
- 新布局单元、Electron、视觉、键盘和 Reduced Motion 测试通过；
- macOS、Windows、Linux package verifier 通过；
- 默认 1024×576 无横向溢出；
- 200% 缩放核心操作可达；
- 拖动 p95 帧预算达标。

## 16. 建议批准的三个产品决策

为避免实施中再次反复，建议本 Proposal 同时批准以下默认决策：

1. **跨页面拖动采用“固定副本”，不是从源页面搬走。**
2. **连接控制与错误恢复属于固定安全区，用户只能排列其余卡片。**
3. **新安装默认窗口采用 1024×576；已保存过窗口尺寸的用户不被强制重置。**

若用户批准本文，下一步才执行：

1. 创建 Goal；
2. 将本文验收标准绑定为 Goal 的完成条件；
3. 按 Phase 0 开始 RED 测试与多 Agent 并行实施。
