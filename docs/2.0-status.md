## Current support statement

- HKUST(GZ) is the only packaged reviewed school Profile.
- `Other school` is visible in packaged 2.0 builds. It uses a credential-free public probe, one-use exact-origin
  confirmation, isolated storage and persistent unverified presentation; it does not by itself prove password
  auth, L3, Campus DNS, MFA or resource support.
- The repository supports multiple isolated Profile candidates and one active Profile at a time. It does not yet
  claim formally reviewed multi-school production compatibility.
- The production Gateway provider remains password + Modern L3. Generic MFA/control types and synthetic tests
  do not constitute a real school MFA provider.

## Local beta evidence

- `/Applications/hkustgzconnect.app` is the sole retained local App and reports `2.0.1-beta.3`.
- Package verifier and `codesign --verify --deep --strict` passed with an Apple Development identity.
- The packaged arm64 Engine depends only on `/usr/lib/libiconv.2.dylib` and `/usr/lib/libSystem.B.dylib`.
- Installed Engine startup reported assigned Campus IP, Gateway DNS and a loopback listener on `127.0.0.1:6180`.
- A SOCKS request to the school homepage returned HTTP 200. The HPC hostname resolved and completed HTTPS;
  the tested `/login` path returned HTTP 404 rather than a DNS/tunnel failure.
- A real installed Mihomo binary accepted the generated-compatible rule configuration and reached the school
  homepage through Mihomo → Campus Connect with HTTP 200; the disposable test configuration was removed.
- Exact-source CI `32901103611`, compatibility watch `32901103651` and three-platform build `32901143519`
  completed successfully. macOS, Windows and Linux packages all passed their verifier and launch smoke gates.
- Tag build `32925749302` completed successfully on its second macOS attempt after one isolated runner timing
  failure; the exact network-startup E2E also passed 5/5 locally before the rerun. The Release contains only
  two DMGs, one EXE and one AppImage and remains explicitly marked Pre-release.
- The local canaries are staff test evidence; publishing the Beta does not constitute another school's
  compatibility proof.

## Deferred work after the accepted Beta

1. maintain the published `2.0.0-beta.1` without expanding the product into SSH/HPC/Jupyter clients;
2. use the requested `2.0.1-beta.*` line for later small fixes; the update checker has an explicit same-line
   Beta-to-patch-zero-final promotion rule because SemVer ranks `2.0.1-beta.*` above `2.0.0`;
3. keep the v1.2.3 migration fixture and three-platform package gates green for every Beta update;
4. add a second reviewed Profile before claiming reviewed multi-school compatibility;
5. if the school later enables Gateway MFA, open a separate task and implement it only from authorized,
   sanitized school evidence;
6. decide on a formal stable release independently after any newly requested capability has its own evidence.

The application remains Web-resource-first for ordinary users and exposes external-tool configuration for
advanced users. It does not add an SSH client, HPC manager, Jupyter/database launcher or `ForwardLease`.
