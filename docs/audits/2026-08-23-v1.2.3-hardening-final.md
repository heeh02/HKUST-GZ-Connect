## 3. 分阶段结果

### Phase 0：基线

确认原始基线：Desktop 483 passed；Rust 215 passed、2 ignored；fmt、Clippy、
npm audit、架构门、same-window/popup MFA、strict proxy、Main integration、layout、
restart、idle 和离线性能门均通过。

同时确认：已有本地 macOS arm64 包不能作为新版本证据；`desktop/release/mac`
不是有效 x64 构建；Windows/Linux 没有本地新包。

### Phase 1：cancel 正确性与可取消认证

已确认的问题：

- `AuthControlSession::handle(Cancel)` 先 `owner.take()`、后验证 context；stale cancel
  会通过 Drop 清理仍有效的 transaction。
- production password HTTP 在 Tokio runtime 主流程同步阻塞，认证期间 control/signal
  无法被主循环消费。

修改：

- `AuthTransactionOwner::cancel(&mut self)` 先校验 generation / transaction / epoch /
  request，再消费 provider state。
- stale/duplicate cancel 保留事务；valid cancel 一旦开始即为终态；provider cleanup
  失败返回稳定 error 且 Desktop 清 UI。
- 新增 `engine/auth_lifecycle.rs`，同步 password HTTP 在 blocking worker 中运行；
  shutdown、pipe EOF、signal 和 deadline 可取消 generation，晚到 session 会 logout。

回归：stale、duplicate、valid、cleanup failure、respond/resend race、cancel 后响应、
exactly-once、shutdown during auth、pipe EOF 和 Desktop pipe 全覆盖。

提交：`0e1e4ea fix(auth): preserve active transaction on stale cancel`。

### Phase 2：稳定认证结果

已确认的问题：所有认证异常最终映射 `AUTH_FAILED`，Desktop 固定显示“账号或密码
错误”，会把 timeout/reset/partial/malformed 误报为用户凭据错误。

新增 primary codes：

- `AUTH_REJECTED`：仅验证过的结构化 `PasswordRequired`；
- `AUTH_INDETERMINATE`：timeout/reset/partial 或无法确认的 HTTP 结果；
- `AUTH_PROTOCOL_INVALID`：响应违反已验证 schema/bounds；
- `AUTH_EXPIRED` / `AUTH_LIMIT_EXCEEDED`；
- `AUTH_CLEANUP_UNCONFIRMED`：只作为 `secondaryCode`，不覆盖 primary。

`AUTH_FAILED` 仅保留旧 Engine 兼容。新 indeterminate/protocol/cleanup 结果全部停止
盲目自动重试，Desktop 不依赖 Rust 英文 error string。

提交：`055cb45 refactor(auth): add stable authentication outcomes`。

### Phase 3：Engine-owned AuthBudget

本地安全上限，不是 EasyConnect 协议事实：

| 预算 | v1.2.3 ceiling |
| --- | ---: |
| 总 monotonic deadline | 4 minutes |
| challenge steps | 10 |
| submits | 6 |
| resends | 4 |
| continuation gateway requests | 32 |
| response | 4096 bytes |
| replay IDs | 64 |

自定义 policy 只能收紧。submit/resend 在 provider 前扣减；future provider 必须通过
Engine 发出的 `AuthGatewayRequestBudget` 在每次 continuation 网络请求前取额度。
Renderer 无操作时，Engine timer 仍会主动 expiry + exactly-once cleanup。

提交：`eb7e80d fix(auth): enforce Engine-owned authentication budgets`。

### Phase 4：Campus Browser 模糊 secret

已确认：原 `loginPasswordInput()` 接受任意首个 password field；原
`loginUsernameInput()` 把任意 text/tel 当 username evidence。

v1.2.3 只有以下任一证据成立才允许 autofill/capture：

- 明确 username/account/email 语义；或
- password 明确 `autocomplete=current-password`。

无文案、无 username、单一 `type=password` 和 numeric secret 在读取 value 前被拒绝。
没有假设 OTP 固定长度。传统 account+password、显式 password-only、SPA、popup、
cross-origin SSO、SameSite、password change/reset 全回归。

提交：`c942d4d fix(browser): reject ambiguous secret fields`。

### Phase 5：Renderer lifecycle 与 Windows DACL

Renderer：control renderer 的 reload/navigation、`render-process-gone`、destroy 会让
Main 清 UI 并 best-effort 发送独立 cancel；in-flight submit 不阻塞 lifecycle cancel，
晚到 provider 输出不能复活 UI。最小化/隐藏不取消。

Windows sidecar：新临时文件在 rename 前通过 PowerShell/.NET 设置 current-user SID
only DACL、关闭继承并验证；提交后再验证。已存在且内容相同的 plaintext sidecar 也
重新保护/验证。任何失败删除未确认安全的 sidecar。路径仅通过子进程环境传递，不
插入 PowerShell script 或日志。

本机 mock/contract 通过；真实 Windows 测试在新增 `windows-private-file` CI job 中，
本轮因未 push 仍为 remote-CI pending。

提交：`0c541ff fix(desktop): cancel auth on renderer loss and protect Windows sidecars`。

### Phase 6：同校园 DNS TCP fallback

原行为：`dns.rs::resolve_with_server` 只发 UDP；parser 看到 TC 直接失败。

新行为：

```text
selected campus DNS:53
  -> UDP via VirtualNetstack
  -> normal matching answer: parse/cache
  -> matching txid + exact question + TC=1
       -> TCP to the same validated endpoint via VirtualNetstack
       -> 2-byte length prefix, <=16 KiB, exact response validation
```

UDP/TCP 共用一个 per-server timeout；多 server 继续并发 first-valid-success。不会因
UDP timeout/error 自动 hedge TCP，也不新增 system/public/secondary fallback。
TCP transport 拆到 `engine/dns/tcp.rs`，DNS 不依赖 authentication provider。

测试覆盖 normal、TC、wrong txid/question、partial length/body、oversize、TCP TC、
timeout/cancellation、cache、singleflight 和多 server race。

提交：`9519aac fix(dns): retry truncated campus responses over TCP`。

## 5. 安全与兼容性判断

保持：

- production Gateway 仍为 password-only；未知/未支持认证 fail-closed；
- Control v2 secret-free，v3 secret-bearing 且 bounded/zeroizing；
- Cookie、TwfID、CSRF、Modern/transport token 不进入 Renderer；
- OTP 不进入 settings、vault、log、telemetry、clipboard 或 crash report；
- password-only、SOCKS5、HTTP CONNECT、普通 HTTP、WebSocket、Clash、SSH 路径回归；
- listener 只在 loopback；旧用户 compatibility 选择保留明确迁移路径；
- DNS 仅走隧道 selected resolver；不修改系统 DNS、route、global proxy；
- 未修改 `special_tls11` 和 Modern data-plane wire 实现。

此前偶发“密码正确却显示账号/密码错误，随后必须重启应用”的问题：v1.2.3 已修复
两个直接相关的代码缺陷——网络/partial 结果不再误报密码错误，认证期 shutdown/EOF
可取消且 partial/late session 有 bounded cleanup。它应消除已识别的假诊断和本地
stranded lifecycle 路径。但本轮没有真实账号、没有复现当时 gateway 响应，因此不能
声称该现场问题已被真实环境 100% 证明根除。
