## 1. 产品问题诊断

以下诊断基于对当前软件的实际运行（Electron 43，控制壳 + 校园工作台窗口，mock 引擎下逐页截图）与源码审读，非凭空推断。截图证据见 `shots/current-*.png`（本次评审留档）。

### 1.1 方向性问题：校园网站页是"文件夹列表"，不是工作台

当前"校园浏览"页把 12 个官方分类渲染成 12 根圆角白条（`desktop/renderer/components/card-board/card-board.css`），用户看到的第一屏是：

- 一排排含义相近的分类名 + 数量 + 箭头，**没有任何一个真实网站直接可见**。
- 想看 SIS、Canvas 必须先点分类 → 分类在原位展开 → 页面被撑高、下方内容被推移。
- 在 1440×900 宽屏下，12 根白条堆在左上三列，**页面下半部分是大面积空白**（实测截图确认），宽屏优势完全浪费。
- 学生真实任务（"我要报销""我要查成绩""我要申请在读证明"）需要先理解学校的 12 分类行政划分，再猜事项在哪个分类里 —— **信息架构是学校视角，不是学生任务视角**。

### 1.2 当前"牌堆"为什么像文件夹（技术根因）

当前实现（`desktop/renderer/components/card-board/`）在数据层确实是"deck"，但**视觉与交互层把它做成了文件夹**，根因有六条：

1. **折叠卡只剩一根 43px 的标题条**：body 用 `hidden` 完全隐藏（`card-board-view.js`），用户看到的是"标题条列表"，而不是"一叠有前后层关系的实体卡"。
2. **用户分组图标直接画成文件夹**（`card-board-icons.js:29-31`），心智模型被图标锁死。
3. **堆叠靠负边距 + 逐级内缩**：`.cb-card + .cb-card { margin-top: -9px }`（`card-board.css:78`），后层卡用 `--cb-stack-inset` 3–15px 向内缩窄（`card-board.css:79-90`）。这不是"同尺寸扑克牌叠放"，而是"越来越窄的纸片子层叠"，视觉上更像手风琴褶。
4. **点击行为是"展开/收起"而不是"抽卡"**：`toggleExclusiveExpandedPlacement`（`card-board-model.js:289-293`）切换 body 显隐，前排卡不会退到后层、后层卡不会来到前排，没有层级置换。
5. **展开改变文档流高度**：body 在正常 grid 流里（`card-board.css:7` 无高度补偿），展开即撑高页面、推移其他内容，滚动位置被破坏。
6. **自动堆叠不受用户控制**：`dealUnits()` 在窗口高度 < 700px 时只给 1 行槽位，超出分类被强制合并成 `auto-deck-*`（`card-board-model.js:32-36, 230-276`）。窗口一矮，分类自动被"收进堆"，用户无法理解为什么分类消失了。

结论：**不允许在此实现上继续改颜色、阴影、圆角**。数据层（document/draft/repair）可保留，视觉层与交互层整体废弃重写（见 §10 真正扑克牌堆）。

### 1.3 其他已核实的问题

| # | 问题 | 证据 |
|---|------|------|
| P1 | 官方服务、个人分类、日程、借阅、资讯没有模块边界 —— 因为后三者根本不存在 | 全仓无日程/借阅/资讯数据模型与 UI |

## 3. 最终信息架构

### 3.1 应用层 IA（四入口，无通知入口）

```
HKUST(GZ) Connect
├── 连接            ← 产品核心，默认页
├── 校园工作台      ← 本次重构主角（原"校园浏览"页升级并改名）
├── 控制塔          ← 高级（侧栏底部）
└── 设置            ← 侧栏底部；通知铃铛在设置页标题右侧
```

- 侧栏顶部高频区：**连接、校园工作台**；底部高级区：**控制塔、设置**。
- **"校园浏览器"** 仍指应用内多标签浏览器窗口；**"校园工作台"** 是承载应用、分类、日程、借阅、资讯的页面。两者关系：工作台每个条目点击后 → 在校园浏览器新标签打开。
- 优先级：连接 > 校园工作台 > 我的分类 > 高级网络配置 > 设置/通知/诊断。

### 3.2 校园工作台 IA（四模块，严格独立）

```
校园工作台
├── 网站与服务模块          ← 唯一有内部标签的模块
│   ├── 官方服务台（默认）
│   │   ├── 我的应用卡（全部/协同办公/教学科研/校园生活/AI 智能体广场）
│   │   └── 学生服务台卡（全部/学术管理/科研管理/校园生活）
│   └── 我的分类
│       └── 用户牌堆 / 简单多列分类（牌堆不达标时的降级方案）
├── 我的日程模块            ← 独立加载、独立错误域
├── 图书借阅模块            ← 独立加载、独立错误域
└── 校园资讯模块            ← 独立加载、独立错误域
```

铁律：

- "官方服务台 / 我的分类"标签**只替换网站与服务模块内部内容**；日程、借阅、资讯不隐藏、不重载、不重排、不重置状态、不改变滚动位置。
- 我的应用与学生服务台**同时展示**，不得互斥、不得互相叠成牌堆。
- 日程、借阅、资讯**不属于**官方服务台，也**不属于**我的分类。
- 官方服务台内**禁止**出现：日程、借阅、资讯、用户文件夹、连接状态、网络诊断、控制塔入口。

## 5. 网站与服务大模块与局部标签切换

### 5.1 标签样式（对齐 myPortal 文字标签）

```
官方服务台      我的分类
──────────
```

| 属性 | 值 |
|---|---|
| 字体 | 15px / Semibold |
| 当前标签颜色 | HKUST 深蓝 `--color-brand-navy` |
| 非当前标签 | 中性灰蓝 `--color-text-muted` |
| 指示线 | 2.5px 高、与文字等宽、深蓝、圆角 2px |
| 标签间距 | 32px |
| 背景/边框/胶囊 | **一律不用** |
| 默认选中 | 官方服务台 |
| 语义 | `role="tablist"` / `role="tab"` / `aria-selected` |

### 5.2 切换行为

- 仅 `ServiceWorkspaceModule` 内部内容替换；**模块自身在页面中的几何位置不变**。
- 内容切换：150–180ms `opacity` + ≤8px 横向位移（`transform`）；Reduced Motion 下直接切换。
- 高度处理：两个视图各自高度不同是允许的，但切换瞬间**不得推挤日程/借阅/资讯模块的横向布局**，且页面滚动位置保持。
- 切换后键盘焦点进入新视图第一个有效控件。
- 搜索框 `placeholder` 与作用域随标签切换（见 §13）。

### 5.3 状态归属

`activeTab` 状态属于 `ServiceWorkspaceModule` 内部，**不得上提为页面级状态**。日程/借阅/资讯的 React/DOM 子树（或 Web 组件子树）在标签切换时不得重新挂载 —— 实现上用 CSS 级显隐或同级交换两个已挂载视图，而不是销毁重建。

## 8. 官方区域交互方案 A/B 对比与推荐

- **方案 A（官网式标签过滤）**：我的应用/学生服务台各自顶部一排轻量分类标签，点击即时过滤列表。全部内容默认直接可见。
- **方案 B（卡片内部扑克牌分类切换）**：每张卡内部把分类做成可抽换的牌页，抽到"教学科研"页显示该分类内容。

| 指标 | A 标签过滤 | B 卡内牌页 |
|---|---|---|
| 直接性 | ★★★★★ 默认全部可见，零抽卡 | ★★★ 正面页可见，其余需抽 |
| 颜值 | ★★★★ 克制 | ★★★★ 有质感但易过重 |
| 动效质量 | ★★★ 120ms 淡入即可 | ★★★★★ 若做到 60fps FLIP |
| 窄窗口（440px） | ★★★★★ 标签可横滚 | ★★★ 牌页需要最小宽度 |
| 首次理解成本 | ★★★★★ 与 myPortal 一致 | ★★★ 需建立抽卡心智 |
| 可访问性 | ★★★★★ 标准 tab 语义 | ★★★★ 需自定义 aria |
| 实现复杂度 | ★★★★★ 低 | ★★ 高（两个堆同时质量难保） |

**推荐：官方服务台采用方案 A。**

理由：官方区是高频效率区，直接性与首次理解成本权重最高；§10 规格明确"不同时制造两个视觉过重的复杂牌堆"。扑克牌动效集中在**我的分类**（§9/§10）——那是用户的个人空间，牌堆的情感价值与"我的收藏夹"心智契合，且全页只需维护一组牌堆质量标准。方案 B 作为备选保留在案，若未来官方区分类数量膨胀再评估。

## 10. 真正扑克牌堆

### 10.1 结构：同尺寸实体卡 + 固定槽位

```
槽位（固定宽高，position: relative）
├── 后层卡2  ┌──────────────────────┐  ← 完整实体卡，被遮挡，只露出顶部 36px
│            │ 🧪 科研计算        5 │     可见区含：图标+名称+数量
├── 后层卡1  │┌────────────────────┐│
│            ││ 📚 文档资料      4 ││
├── 正面卡   ││┌──────────────────┐││
             │││ 💰 报销申请    4 │││
             ││├──────────────────┤││
             │││ PBMS    E-Form  │││
             │││ E-Tender 一站式 │││
             │││         查看全部 │││
             ││└──────────────────┘││
             │└────────────────────┘│
             └──────────────────────┘
```

铁律：

1. **每张卡几何尺寸完全一致**（同槽位同宽高），后层是完整渲染的实体卡（含内容区，仅被遮挡），不是标题条、不是越来越窄的纸片。
2. 后层沿槽位顶部依次偏移，每层**只露出 36px 标题区**（图标 22px + 分类名 + 数量）；第 1 层偏移 36px、第 2 层 72px，超过 2 层后层不再增加（**自动牌堆最多 3 张**）。
3. 点击后层露出区 → 该卡**抽到正面**，原正面卡**退到后层**（层级置换，z-index 重排）。**点击正面标题不折叠** —— 牌堆没有"收起"概念。
4. 牌堆占据**固定槽位**：抽卡不改变槽位几何、不改变页面高度、不改变滚动位置、不推移兄弟牌堆和其他模块。
5. 禁止用 `height` 动画模拟展开；禁止把后层渲染成独立圆角标题行。
6. 同一牌堆同时只有一张正面卡；内容超出预览数显示"查看全部"，**不用永久内层滚动条**；内容区宽度 ≥360px 时两列排布网站。

### 10.2 尺寸规范（CSS 像素）

| 档位 | 槽位宽 | 正面卡内容预览 | 适用 |
|---|---|---|---|
| 小卡 | 1 列（≈320） | 4 个网站（单列） | 窄窗 / 内容少 |
| 中卡 | 1 列（≈400） | 6 个网站（两列×3） | 默认 |
| 大卡 | 2 列跨距 | 8 个网站（两列×4） | 宽屏 / 大分类 |

- 正面卡高 = 标题 56px + 内容区（每行 44px）+ 查看全部 40px；同尺寸档内高度一致，内容不足时用占位行撑齐 —— **尺寸一致优先于内容贴合**。
- 后层卡悬停：再多露出 4px（向上平移 -4px），阴影略增强，光标 pointer，**不推动任何其他卡**。

### 10.3 牌堆与页面的关系

- 我的分类区是牌堆的网格容器：440px 一列、820px 两列、1440px 三至四列。
- 网格 `align-items: start`，但**抽卡永远不改变任何槽位尺寸**，因此网格从不重排。
- 单卡（不属于任何堆的分类）也使用同一卡件，只是槽深为 1。

## 11. 抽卡动画逐帧说明

总时长 **240ms**（220–260ms 区间）。只允许 `transform` 与 `opacity`。实现：优先 FLIP（记录前后位置 → 反向 transform → 播放），或 Web Animations API 合成关键帧；`will-change: transform` 仅在动画期间设置。

时间轴（0–240ms，缓动 `cubic-bezier(.2,.7,.2,1)`）：

| 时间 | 目标后层卡 | 原正面卡 | 其余后层卡 |
|---|---|---|---|
| 0–60ms | 向上抽出 `translateY(-14px)`，`scale(1.015)` | 保持 | 保持 |
| 60–160ms | 沿短弧线（贝塞尔中点向外偏 8–12px）滑向正面槽位 | 向后下沉 `translateY(+8px)`、`scale(0.985)` | 各自向上递补一层（`translateY(-36px)`，同步 180ms） |
| 160–240ms | 到位，scale 回 1.000；卡内容 `opacity 0→1`（80ms 淡入） | 到位进入后层目标层，露出 36px 标题 | 到位 |

关键细节：

- z-index 在动画**开始帧**即完成置换（目标卡立即置顶），避免穿插闪卡；位移靠 transform 表达。
- 阴影不做动画（box-shadow 仅两档静态值，前后切换帧交换，见 §22）。
- 全程页面 `scrollTop` 不变、兄弟元素 `getBoundingClientRect()` 不变 —— 这是验收测试项（§28）。
- 目标 60fps：动画期间无布局读写穿插（FLIP 的一次性测量在动画前完成）。
- 连续快速点击不同后层卡：动画可中断，新动画从当前 transform 状态接续（WA PI `element.animate` 天然支持），不得排队堆积。
- **Reduced Motion**：取消一切位移动画，仅 100ms 交叉淡入完成层级切换。

| 默认 | 正面卡白底 + §22 正面阴影；后层露 36px，浅灰蓝底（`--color-panel`），无重阴影 |

## 13. 搜索交互

### 13.1 作用域

搜索框属于网站与服务模块，**作用域跟随当前标签**：

- 官方服务台：`placeholder = "搜索应用或办事事项，如：报销、在读证明、HPC2"`。
- 我的分类：`placeholder = "搜索我的网站或分类"`。
- 搜索进行时只过滤网站与服务模块；日程/借阅/资讯**绝不受搜索影响**。

### 13.2 官方自然语言搜索

- 数据基础：每条官方资源/事项扩展 `useCase`（一句用途）、`audience`（适用人群）、`aliases`（中文俗称/英文缩写/同义词：报销↔采购与报销申请↔PBMS；在读证明；成绩↔SIS/KLMS）。**废弃 `REVIEWED_HINTS` 硬编码与关键词猜受众**（`campus-search-presenter.js:12-51`），结构化数据进资源文档。
- 匹配：名称 > 别名 > 用途 > 关键词；朴素子串 + 打分排序即可，不引入重型搜索库。
- 结果行：图标 + 名称 + 一句用途 + 适用人群 + 所属区域徽标（我的应用 / 学生服务台）+ 直连/校园隧道。**命中具体网站/事项，不返回整个分类**。
- 支持任务句式："我要申请在读证明""我想报销" → 去除"我要/我想/申请"等停用词后命中事项。
- 无结果："没有找到「X」· 试试 myPortal 搜索 →"。

### 13.3 我的分类搜索

- 匹配用户分类名、网站名、描述、用户自定义关键词。
- 命中分类 → 直接聚焦该分类卡（抽到正面）并高亮；命中网站 → 结果行直达。

### 13.4 退出搜索

Esc 或清空输入后恢复：之前的标签、之前的牌堆正面状态、之前的页面滚动位置。搜索状态不写入任何持久层。

## 23. 可访问性

- **键盘**：Tab 顺序 = 搜索 → 标签 → 卡片内容 → 日程 → 借阅 → 资讯；牌堆内左右方向键切换目标卡、Enter/Space 抽到正面、Esc 退出整理/拖动；标签为标准 `tablist` 键盘行为（←/→）。
- **焦点**：全局 2px 深蓝 focus ring；标签切换后焦点落到新视图第一个控件；抽卡后焦点跟随新正面卡标题；展开日程后焦点进周视图工具行。
- **读屏**：牌堆 `role="tablist"`/`tab`（或 `listbox`/`option`），正面卡 `aria-selected="true"`；后层卡 `aria-label="科研计算，5 个网站，第 2 张，共 3 张"`；日程周视图用 `table` 语义或 `grid`；未读点 `aria-label="未读"`；所有图标按钮有 `aria-label`。
- **Reduced Motion**：`prefers-reduced-motion` 下取消位移/抽卡动画，仅 ≤100ms 淡入；标签切换瞬时完成。
- **对比度**：正文 ≥4.5:1，辅助文字令牌已保证 ≥4.7:1；状态不靠单一颜色传达（逾期 = 红 + "已逾期"文字）。
- **缩放**：125%/200% 见 §21.6。

## 24. 数据状态设计

三个数据模块（日程/借阅/资讯）各自实现完整状态机，**互不共享 loading/error**：

| 状态 | 日程示例表现 | 通则 |
|---|---|---|
| 未登录 | "登录学校账号后查看日程 [去连接页登录]" | 给明确下一步 |
| 登录中 | "正在登录学校账号…" | 不闪烁 |
| 加载中 | 骨架行（灰条呼吸） | 不用全页 spinner |
| 正常 | §14–16 规定内容 | — |
| 空数据 | "今天没有日程"（数据源**确认**为空才可显示） | 空≠失败 |
| 无权限 | "当前账号无权访问课表服务 [了解详情→]" | 给官方入口 |
| 会话过期 | "登录已过期 [重新登录]"，保留最后已知数据灰显 | 可一键续期 |
| 数据源不可用 | "学校课表服务暂不可用 [重试] [打开官方页面→]" | 给降级入口 |
| 隧道未连接 | 仅当该数据源必须走隧道时："连接校园网络后可用 [去连接]" | 可直连源不受限 |
| 加载失败 | "加载失败 [重试]"，整模块限高 120px 内 | **不得撑破布局** |

铁律：**任何"读不到"不得渲染成"没有"**；任何模块失败不撑破布局、不阻塞兄弟模块；未获数据不得伪造。

## 26. 数据与安全边界

- 认证：学校官方账号会话由主进程持有（safeStorage + 校园浏览器 session partition），**Renderer 永不保存密码**；EasyConnect 凭据不下发到任何门户页面；日程/借阅/资讯数据获取复用已登录会话，经主进程代理调用，渲染层只拿脱敏投影。
- 数据源优先级：学校正式 API > 受控已登录浏览器会话 > 官方页面深链 > 可选本地 ICS 导入；**DOM 抓取不得作为唯一数据源**。
- 日志：不记录敏感 URL 参数、凭据、Cookie；诊断日志仅保留状态码与时间。
-  IPC：沿用 `registerTrustedIpcHandlers` 白名单；新增通道（schedule/loans/news）按同规格注册，渲染层参数全部走 schema 校验（对齐 `campus-resource-contract.js` 的做法）。
- 伪造红线：未获得数据时不得生成假日程/假借阅/假资讯；"数据源不可用"与"没有内容"严格分流（§24）。

## 28. 验收标准

### 28.1 视觉回归（自动化）

- 五档窗口（440×540、820×540、1024×576、1280×720、1440×900）+ 125%/200% 缩放截图基线比对：无横向溢出、无元素重叠、焦点环可见。
- 标签切换前后：日程/借阅/资讯三模块的 `getBoundingClientRect()` 与内部状态快照**逐像素一致**（允许网站与服务模块自身变化）。
- 抽卡前后：页面 `scrollTop` 不变、兄弟牌堆 rect 不变。

### 28.2 牌堆原型验收（门禁）

- 用户 3 秒内识别为扑克牌堆而非文件夹（5 人盲测 ≥4 人答对）。
- 点击一次完成抽卡；动画 220–260ms；`requestAnimationFrame` 采样 ≥55fps。
- 后层分类名清晰可读；自动堆 ≤3 张；同尺寸实体卡（卡间宽高差 ≤1px）。
- 440px 无横向溢出；1024px 首屏直接见 ≥8 个高频网站。
- 官方服务与个人分类不同时显示；三数据模块不受切换影响。
- Reduced Motion 下无位移动画；键盘全流程可操作；`aria-selected` 正确迁移。
- 4/5 首次用户无指导完成"切标签 + 抽卡 + 打开网站"。
- GUI 盲测 ≥8.5/10。**不达标 → §9.3 降级，删除牌堆。**

### 28.3 功能验收

- 搜索："报销"→ 采购与报销申请（单条命中，非整个分类）；"HPC2"→ HPC2 且标注校园隧道。
- 日程十态（§24）逐一可走查；借阅无续借接口时界面无续借按钮。
- 连接开关在所有档位位置固定；未连接无伪造延迟。

### 28.4 性能与跨平台

- 工作台冷渲染 ≤150ms（现有 e2e 性能基线不破）；抽卡期间无长任务 >50ms。
- macOS（hiddenInset 标题栏）、Windows、Linux 三平台窗口最小/默认/最大各档截图走查。

## 30. 两个视觉方向与推荐

**方向一「myPortal 效率」（推荐 ✅）**：浅灰底 + 白内容卡 + 深蓝文字标签 + 金色极少量点缀；信息直接、密度高、零装饰。契合"每天打开几十次的效率工具"定位；与学生已有的 myPortal 使用习惯零迁移成本；可访问性与实现成本最优。

**方向二「纸感牌桌」**：暖米白底（`#faf9f6`），牌堆卡带纸张质感边缘与更明显的桌面投影，金色使用面扩大到标题分隔线，侧栏改为深蓝渐变。颜值高、个性强，但偏离 myPortal 心智、装饰性元素与"删除冗余说明/容器"原则冲突，且投影层级加重性能与 Reduced Motion 复杂度。

**推荐方向一**：把全部"设计亮点预算"集中到我的分类真牌堆一处；其余区域追求无感的高效。方向二的纸感语言仅在牌堆微质感（后层卡顶边 1px 高光）中保留 5%。
