# HKUST(GZ) Connect GUI 实现审计（2026-09-04）

## 结论

当前实现已经完成正确的产品方向切换：侧栏收敛为“连接 / 校园工作台 / 控制塔 / 设置”，校园工作台把官方服务与个人分类做成局部标签，并保留独立的日程、借阅、资讯节点。主要问题已经从“方向错误”变成“首屏密度、窄屏可读性、数据状态与真实接入边界”四类可修问题。

本轮以 `DESIGN.md` 为规范、以 440×540、820×540、1024×576、1280×720、1440×900 的 Electron 截图夹具为观察对象。未使用真实学生账号，也未读取 Cookie、Token、课程、借阅或个人资讯。

## 已实现且应保留

- 四个固定侧栏入口，通知只在设置页使用铃铛抽屉。
- “官方服务台 / 我的分类”只切换网站与服务区域，三个数据模块保持同一 DOM 节点。
- 官方服务台采用直接可见的“我的应用 + 学生服务台”，没有恢复 12 个分类手风琴。
- 我的分类沿用独立牌堆组件，抽卡不改变槽位和页面滚动位置。
- 搜索能从“我要申请在读证明”“报销”“HPC2”直接命中具体事项。
- 整理模式留在当前页面，浏览态不暴露拖动句柄。

## 本轮发现的问题与处理

| 优先级 | 问题 | 学生影响 | 本轮处理 |
|---|---|---|---|
| P0 | 日程、借阅、资讯只有静态文案，没有会话和数据状态 | “读不到”与“没有”无法区分，容易产生错误信任 | 增加十态中的实际状态投影、独立加载与独立失败边界 |
| P0 | myPortal 接入没有 Main/Renderer 安全边界 | 未来容易把 Cookie、Token 或原始响应下发给 Renderer | 增加 Main 进程会话网关和无参数 IPC，只返回受限展示模型 |
| P1 | 1024 宽应用目录与 myPortal 不一致 | 学生找不到门户已授权给当前账号的入口 | 动态同步 myPortal 的 5 分类、34 个账号应用与 23 个学生服务；首屏 12 项，可在当前页展开全部 |
| P1 | 440 宽应用仍是双列 | 标题、用途和路由标签被切碎 | 609px 以下改成单列，缩小内边距但不缩小正文到不可读 |
| P1 | 宽屏数据模块只是散落文字 | 模块边界弱，状态与来源不清楚 | 使用无重阴影的轻量独立卡，显示来源、状态点和唯一下一步 |
| P2 | 加载反馈可能演变成全页等待 | 一个学校源失败会拖累整个工作台 | 每个模块只在自己的 156px 区域内加载/失败，网站服务始终可用 |

## 视觉与交互判断

方向继续采用“myPortal 效率”而不是“纸感牌桌”。品牌蓝负责结构和主操作，金色仅用于校园隧道、临期和未读。白色卡片只用来承载真实模块，不再给每一层信息套容器。

本轮之后的工作台层级：

1. 页面标题与全局搜索。
2. 网站与服务的局部标签。
3. 两张官方任务卡或个人牌堆。
4. 一张横跨内容区的周课表，以及借阅、资讯两个独立模块。
5. “我的应用”和“学生服务台”在窄窗口是同一牌堆中的两张完整实体主卡；默认应用在正面，点击露出的学生服务台卡头完成抽卡。窗口达到 980px 后，两张主卡自动左右并列。各自内部分类继续使用普通标签；“查看更多”使用独立的平铺全面视图。
6. 官方条目末尾只显示收藏星标，网络路径细节集中由控制塔规则库管理。
7. 收藏时可选择已有分类或即时新建分类，保存后自动定位到“我的分类”；个人分类牌堆使用下划线分页导航。
8. “我的应用”在窄窗口和宽窗口都固定为每行两个入口；学生服务台在超宽窗口可使用两列。官方卡片使用紧凑字号与 42px 行高，真实首屏条目和分页不得被卡片边界裁切。
9. 列表悬停不再绘制整行灰色光条，只使用图标、文字与星标的局部缓动反馈；窄窗口抽卡使用 220–240ms 缓动，并遵守 Reduced Motion。

“查看更多”不再通过继续拉长当前卡片解决：我的应用进入 myPortal，学生服务台进入官方办事指南；卡片只承担高频预览。

## 仍需真实学校证据的部分

- 日程与资讯已按授权会话中观察到的只读 JSONP 请求接入，但仍缺学校发布的正式 schema、频率限制与第三方使用许可。
- 图书借阅的正式 API 地址、方法、响应 schema 和权限范围。
- SSO 登录完成后哪些 Cookie/会话标识允许由桌面客户端复用。
- 这些数据源是否要求校园隧道，以及会话过期/无权限的稳定响应码。
- 图书馆是否提供正式续借接口。没有正式接口前，产品只显示借阅状态与官方账户入口。
- 资讯源的可靠订阅格式和分类规则。没有可靠源时只显示学校官网入口。

这些未确认项不会由 DOM 抓取、缓存页面或模拟数据替代。

## 验收重点

- 440px：官方应用单列，无横向溢出，标题和主要操作可读。
- 1024px：首屏至少直接可见 8 个高频应用，网站卡不会因“全部目录”无限增长。
- 1440px：三个数据模块同排，来源、状态和操作对齐，不出现大块无归属文字。
- 三模块分别注入失败时，另外两模块与网站服务节点不重建。
- 未登录、接口待确认、失败、空数据必须是四种不同文案和 `data-state`。
- Renderer API 不存在 Cookie、Token、密码或任意 URL 请求参数。
